# H.6.1 LiveDB_ACE Read-Only Boundary Audit

**Audit date:** 2026-10-15 (~14:35–14:45 +08)  
**Operator:** `FILESERVER1\FILESERVER`  
**Authorization:** Read-only audit only — **no remediation, no permission changes, no patient-data export**  
**Scope:** Boundary between hospital HIS database `LiveDB_ACE` and portal database `ACE_ResultsPortal`

## 3. Database connection architecture

### 3.1 Two pools

| Pool | Module | Env for database name | Default credentials |
| --- | --- | --- | --- |
| Portal | `getPool()` / `loadDbConfig()` | **`DB_DATABASE`** (required) | `DB_USER` / `DB_PASSWORD` |
| HIS | `getHisPool()` / `loadHisDbConfig()` | `HIS_DB_DATABASE` **or** `HOSPITAL_DB_DATABASE` | Falls back to **`DB_USER` / `DB_PASSWORD`** unless `HIS_DB_USER` / `HIS_DB_PASSWORD` set |

### 3.2 Effective targets (config evidence, 2026-10-15)

| Setting | Effective value | Classification |
| --- | --- | --- |
| Portal `DB_DATABASE` | `ACE_ResultsPortal` | VERIFIED |
| HIS database name | `LiveDB_ACE` via `HOSPITAL_DB_DATABASE` | VERIFIED |
| `HIS_DB_USER` / `HIS_DB_PASSWORD` | **Not set** in prod or repo `.env` | VERIFIED |
| Shared SQL login for portal + HIS | **Yes** (`sameUser: true`) | VERIFIED |
| Same SQL server for both | **Yes** | VERIFIED |
| Portal server | `198.15.0.201:1433` | VERIFIED (non-secret) |

### 3.3 Target-selection logic and fallbacks

1. **Portal pool** always connects with `database = DB_DATABASE`. Guard rejects blocked hospital DB names including `LiveDB_ACE` as `DB_DATABASE` (throws before connect).  
2. **HIS pool** connects with `database = HIS_DB_DATABASE ?? HOSPITAL_DB_DATABASE`, refusing if missing, invalid identifier, or equal to portal DB name.  
3. **Credential fallback:** HIS uses portal credentials when `HIS_DB_*` user/password unset — **documented and verified in current env**.  
4. **Alternate path:** `scripts/src/probe-livedb-identity.ts` uses the **portal pool** with three-part names `[LiveDB_ACE].dbo.*` for SELECT probes — does not use `hisRequest()`. Application runtime hospital lookups use `hisRequest()`.

### 3.4 Dynamic database selection

No application write path was found that switches `DB_DATABASE` to `LiveDB_ACE` at runtime. Risk is **privilege breadth of the shared login**, not a mis-named portal database in normal startup.

## 4. SQL identity and effective permissions

### 4.1 Metadata probe method

Read-only connection using configured credentials; queries limited to:

- `DB_NAME()`, `USER_NAME()`, role membership (`IS_SRVROLEMEMBER`, `IS_MEMBER`)
- `HAS_PERMS_BY_NAME(...)` for database and selected objects
- `sys.fn_my_permissions(NULL, 'DATABASE')` (permission **names** only)
- `SELECT TOP (0) ... FROM [LiveDB_ACE].sys.tables` (empty result; existence/rights check)

Login **names** redacted to length only. **No patient rows returned.**

### 4.2 HIS connection (`database = LiveDB_ACE`) — VERIFIED

| Check | Result |
| --- | --- |
| Connected database | `LiveDB_ACE` |
| Database user | `dbo` |
| `IS_SRVROLEMEMBER('sysadmin')` | **1** |
| `IS_SRVROLEMEMBER('securityadmin')` | **1** |
| `IS_SRVROLEMEMBER('dbcreator')` | **1** |
| `IS_MEMBER('db_owner')` | **1** |
| `IS_MEMBER('db_datawriter')` | **1** |
| `IS_MEMBER('db_datareader')` | **1** |
| `IS_MEMBER('db_denydatawriter')` | **0** |
| `HAS_PERMS_BY_NAME` INSERT/UPDATE/DELETE/ALTER/CREATE TABLE | **1** (all) |
| Object sample: `dbo.vwReportPatientProfile` SELECT/INSERT/UPDATE/DELETE | **1** (all) |
| Object sample: `dbo.psPatRegisters` SELECT/INSERT/UPDATE/DELETE | **1** (all) |
| Database permissions list | Includes CONTROL, INSERT, UPDATE, DELETE, ALTER, CREATE TABLE, etc. |

**Verdict:** The identity used for HIS access is **not** demonstrably read-only. It has **effective write and DDL capability** on `LiveDB_ACE`, including on verification-related objects. Application SELECT-only code does **not** make the SQL principal read-only.

**Classification: FAIL** (least-privilege / HIS write boundary at SQL layer)

### 4.3 Portal connection (`database = ACE_ResultsPortal`) — VERIFIED

| Check | Result |
| --- | --- |
| Connected database | `ACE_ResultsPortal` |
| Database user | `dbo` |
| `db_owner` / `db_datawriter` / INSERT | **1** (expected for portal app writes) |
| Cross-db: portal session can resolve `[LiveDB_ACE].sys.tables` | **ok: true** |

Because the same login is shared, the portal session can also reach `LiveDB_ACE` via three-part naming if application or script SQL does so.

### 4.4 Stored procedures / elevated paths

Object-level EXECUTE inventory across all HIS procedures: **NOT VERIFIED** (not exhaustively enumerated). Given `sysadmin` / `CONTROL`, procedure execute capability is effectively present.

### 7.2 HIS / portal name separation

| Guard | Finding |
| --- | --- |
| `loadHisDbConfig` / `loadHospitalDatabaseName` | Rejects missing/invalid name; rejects HIS name equal to portal DB |
| Does **not** require HIS DB to be `LiveDB_ACE` specifically | OPEN/informational |

### 7.3 Application `assertReadOnlySelect`

| Property | Finding |
| --- | --- |
| Applies to | SQL strings in `hospital-patients.ts` before `hisRequest().query` |
| Bypass | Any other module using `getHisPool()` / `hisRequest()` without the assert; raw `mssql` clients; SSMS; three-part DML via portal pool; compromised app injecting SQL that passes the regex poorly |

Regex is a defense-in-depth control, **not** a substitute for least privilege.

## 11. Evidence needed from DBA / application owner

1. Confirm whether the short portal SQL login **must** remain `sysadmin` for other hospital systems (likely should not).  
2. Provide / create a **SELECT-only** login (or role) limited to:
   - `SELECT` on `dbo.vwReportPatientProfile`, `dbo.vwPatientMstrList`
   - `SELECT` on `dbo.psPatRegisters` (or replace EXISTS with a safer view)
   - No INSERT/UPDATE/DELETE/DDL on `LiveDB_ACE`
3. Confirm whether portal login may retain elevated rights on **`ACE_ResultsPortal` only** (db_owner/datawriter) while HIS uses a different login via `HIS_DB_USER` / `HIS_DB_PASSWORD`.  
4. Document dependency of other applications on this login.  
5. SQL TLS certificate package (SAN, CA, trust) for P0-4 — separate from this boundary issue but still open.

## 12. Recommended remediation (separately authorized — **not implemented**)

Priority order:

1. **P0 — Create dedicated HIS read-only SQL login/role; set `HIS_DB_USER` / `HIS_DB_PASSWORD`; remove HIS access from portal-elevated login.** Cutover must **fail closed** if the RO identity fails — do not treat unsetting `HIS_DB_*` (silent elevated fallback) as default rollback. See [H6.1_LIVEDB_READ_ONLY_REMEDIATION_PLAN.md](./H6.1_LIVEDB_READ_ONLY_REMEDIATION_PLAN.md) (§4.1–4.3).  
2. **P0 — Strip sysadmin / db_owner / datawriter on `LiveDB_ACE` from any account used by the portal runtime.**  
3. **P1 — Disallow portal-login three-part access to LiveDB** (DENY or remove CONNECT/SELECT as appropriate after HIS login cutover).  
4. **P1 — Keep `assertReadOnlySelect`; add CI check that `hisRequest` call sites only live under hospital-patients (or shared helper).**  
5. **P1 — Ensure maintenance scripts that touch LiveDB use the read-only login and SELECT-only templates.**  
6. Continue SQL TLS hardening under existing H.6.1 P0-4 (no change in this audit).

Do **not** “test” the boundary by attempting writes against LiveDB_ACE.
