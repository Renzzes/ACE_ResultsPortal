## P0-1 — Firewall scope and origin protection

### Evidence

- Inbound rules (duplicate display name): `ACEMCC ACERPTS TCP 3003`, Enabled, Allow, Profile=Any, LocalPort=3003, RemoteAddress=Any, LocalAddress=Any, Program=Any.
- Node listens on `[::]:3003` (all interfaces). Env has `HOST=0.0.0.0` but `index.ts` calls `app.listen(port)` without host — Node defaults to dual-stack all interfaces.
- No reverse proxy for ACERPTS on 3003. IIS hosts other apps (8080–8089, 8443) but not ACERPTS.

### Severity / impact

**CRITICAL.** Any routable client that can reach FILESERVER1:3003 can speak cleartext HTTP to a PHI application.

### Target state

Aligned with recommended architecture (see Deliverable B):

1. **Preferred (Tunnel-first):** Application listens only on `127.0.0.1:3003`. Cloudflare Tunnel connector on the same host reaches origin via loopback. **No inbound Windows Firewall allow for 3003 from Any.** Delete or disable the Any/Any rules.
2. **If Staff/Admin use LAN split-horizon fallback:** Additionally allow inbound 3003 (or an internal reverse-proxy port) **only** from approved hospital LAN CIDRs and approved VPN pool CIDRs — never Any.
3. Public internet must never connect directly to `192.168.10.55:3003`.

### Intended configuration changes (later, after approval)

| Change | Detail |
| --- | --- |
| Listen bind | Application code/env: bind `127.0.0.1` (Tunnel-only) or explicit approved addresses |
| Firewall | Remove/disable both `ACEMCC ACERPTS TCP 3003` Any rules; replace with deny-by-default + narrow allows if LAN fallback used |
| Tunnel | `cloudflared` service → `http://127.0.0.1:3003` (no public inbound needed for Tunnel) |

### Dependencies

- Decision on primary architecture (Tunnel-only origin vs LAN fallback).
- Application listen-host change (code/config) before removing LAN access if staff currently use `http://192.168.10.55:3003`.
- Documented approved LAN and VPN CIDRs from hospital IT.

### Implementation sequence

1. Freeze CIDR allowlists with IT.
2. Deploy Tunnel to loopback **before** removing LAN access (or schedule staff cutover).
3. Change listen bind.
4. Replace firewall rules.
5. Verify from four vantage points (below).

### Validation

| Vantage | Expected |
| --- | --- |
| Server localhost | `http://127.0.0.1:3003/api/healthz` → 200 |
| Hospital LAN (direct IP:3003) | **Fail** if Tunnel-only; **Succeed** only if LAN fallback intentionally enabled |
| Approved VPN | Same as LAN policy |
| External internet → public IP:3003 | **Fail** (timeout/refused) |
| External → `https://patient.acemccebu.results.com` | Succeeds only after Tunnel+DNS+TLS live **and** separate Go decision |

### Rollback

Restore previous firewall export; revert listen bind; keep Tunnel optional until verified.

### Approval gate

### Target ACL matrix (proposed)

| Path | Administrators | SYSTEM | `ACE_ACERPTS_SVC` (future service account) | Deploy operators (named group) | Authenticated Users / Users |
| --- | --- | --- | --- | --- | --- |
| `D:\ACERPTS\app` (binaries) | Full | Full | Read+Execute | Modify (deploy only) | **None** |
| `D:\ACERPTS\app\.env` | Full | Full | Read | Read (deploy merge only) | **None** |
| `D:\ACERPTS\storage` | Full | Full | Modify | Read (backup ops) | **None** |
| `D:\ACERPTS\logs` | Full | Full | Modify | Read | **None** |
| `D:\ACERPTS\backup` | Full | Full | None or Read | Modify | **None** |
| Repo `.env*` | Full | Full | None | Modify (devs) | **None** |

`ACE_ACERPTS_SVC` is a **dependency** — create before applying ACLs if migrating off SYSTEM in the same window; if ACL work precedes identity migration, grant SYSTEM only (already present) and remove broad groups.

### Safe implementation sequence (later)

1. `icacls` / `Get-Acl` export for every path (before-state evidence).
2. Confirm deploy script identity (OneClick / interactive admin today).
3. Confirm backup/rollback still works for Operator group.
4. Break inheritance where needed; apply explicit ACEs; remove Authenticated Users / Users.
5. Test: start app, upload/download result, write log, OneClick backup, watchdog restart.
6. Keep ACL export backup for rollback (`icacls /restore`).

### Risk of breakage

- Interactive non-admin developers writing into `D:\ACERPTS` will lose access (desired).
- OneClick run by a user not in Deploy Operators group will fail — document required group.
- Antivirus / backup agents that relied on Authenticated Users may need explicit ACEs.

| Option | Fit | Notes |

### Migration without unnecessary downtime

1. Create account; set password in approved secret store; deny interactive logon if policy allows.

3. Update both scheduled tasks to the new principal (Least privilege run level).

5. Rotate secrets afterward if SYSTEM-era `.env` was world-readable (P0-5).

### Evidence

- Driver: `mssql` (Tedious) via `lib/db/src/pool.ts` / `his-pool.ts`.
- Config: `DB_ENCRYPT`, `DB_TRUST_SERVER_CERTIFICATE` (defaults encrypt=false, trustServerCertificate=true).
- Deployed: `DB_ENCRYPT=false`, `DB_TRUST_SERVER_CERTIFICATE=true`.
- Portal DB host: `DB_SERVER=198.15.0.201`, database `ACE_ResultsPortal`.
- HIS: `HOSPITAL_DB_DATABASE=LiveDB_ACE` (read path only; **no LiveDB writes in this plan**).
- LiveDB name guard in `loadDbConfig()` **must be preserved**.

### Severity

**HIGH** for LAN credential/PHI interception between app and SQL hosts.

### Target state (production)

| Setting | Target | Notes |
| --- | --- | --- |
| `DB_ENCRYPT` | `true` | Require TLS to SQL |
| `DB_TRUST_SERVER_CERTIFICATE` | `false` | Validate server cert |
| SQL Server | TLS enabled with cert whose SAN/CN matches the connection host name clients use | Coordinate with DBA |
| Windows trust | Host trusts issuing CA | Install CA if private PKI |
| HIS overrides | `HIS_DB_ENCRYPT` / trust vars if split | Same production bar |
| `DB_SERVER` | Prefer DNS name matching certificate SAN | **PREFERRED** by owner; **DBA confirmation pending** — do not change production until confirmed |

**Do not** treat `trustServerCertificate=true` as a permanent production control. If used briefly during cutover while certs are fixed, label **time-limited exception**, ticket it, and expire it.

### Staged test plan (non-production first)

1. On a **test SQL instance** or approved non-prod database (never LiveDB_ACE writes): enable TLS, confirm `encrypt=true` + `trustServerCertificate=false` connects.
2. Validate hostname used in `DB_SERVER` matches certificate SAN (prefer DNS name — owner **PREFERRED**; await DBA).
3. Only then change production env in a maintenance window; verify `/api/healthz` and a read-only portal login.
4. Do **not** run load tests against LiveDB_ACE.

### Dependencies

- DBA-provided certificate status (issuer, SANs, trust chain, TLS support) — **NOT VERIFIED** in this phase.
- DBA confirmation of DNS name vs current IP endpoint before any production `DB_SERVER` change.

### Approval gate

## P0-6 — HTTPS, secure cookies, CORS, and proxy trust

### Evidence (source)

- Cookies: `HttpOnly`, `SameSite=Lax`, `Secure` when `NODE_ENV=production`, `path=/api/auth`, **no Domain attribute** (host-only) — good default.
- CORS: explicit allowlist from `CORS_ORIGIN`; rejects `*` in production; allows requests with **no Origin** header.
- `trust proxy` = `1` (first hop) — acceptable only if the sole reverse proxy/tunnel is trusted; dangerous if clients can hit Node directly with spoofed forwarded headers.
- Single Express app serves SPA + `/api` for patient, physician, staff, and admin **path prefixes** — subdomains are **not** currently enforced.
- WebSocket `/api/messages/live` authenticates via token frame after connect (source).
- Rate limits exist on auth/portal/support (e.g. login 20 / 15 min) — presence verified; effectiveness under abuse is H.6.4 scope.

### Target behavior for production HTTPS

| Control | Target |
| --- | --- |
| External TLS | Terminated at Cloudflare (Full (strict) to Tunnel). Clients always HTTPS. |
| Origin | HTTP to `127.0.0.1` **only** over Tunnel loopback (not public cleartext) |
| Cookies | Keep `Secure` + `HttpOnly` + `SameSite=Lax`; **do not** set `Domain=.acemccebu.results.com`; prefer host-only cookies per subdomain |
| CORS | Exact HTTPS origins only: `https://patient.acemccebu.results.com`, `https://doctor.acemccebu.results.com`, `https://staff.acemccebu.results.com`, `https://admin.acemccebu.results.com` (plus approved LAN origins only if a documented fallback requires them) |
| Host gating (app change required) | Reject wrong portal roles / path prefixes for each `Host` (see Deliverable B) |
| `trust proxy` | Keep `1` **only** after direct :3003 is unreachable from untrusted networks; document that Cloudflare/Tunnel is the trusted hop |
| WebSocket | Same Host + Access policy as parent portal; wss through Cloudflare |

### Code vs infrastructure

| Change | Layer |
| --- | --- |
| Cloudflare TLS, Tunnel, WAF, Access | Infrastructure |
| CORS_ORIGIN values | Config |
| Host-based portal enforcement | **Application code** (required before public) |
| Cookie Domain | Do **not** broaden |
| Listen bind 127.0.0.1 | App/config |
| Secure cookies | Already on in production; becomes correct once HTTPS is real |
