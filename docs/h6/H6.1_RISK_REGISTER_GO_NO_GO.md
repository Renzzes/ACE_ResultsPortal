## 3. Go / No-Go criteria for public Patient or Doctor exposure

### NO-GO if any remain true

- [ ] TCP 3003 reachable from Internet or firewall still Any/Any  
- [ ] Node listening on all interfaces without compensating FW  
- [ ] `.env` or result storage readable by Authenticated Users / Users  
- [ ] HTTPS not enforced on public hostnames  
- [ ] CORS still lists open HTTP LAN wildcards for production public mode  
- [ ] Host gating not deployed  
- [ ] Staff/admin generally reachable without Access or equivalent  
- [ ] healthz failing  
- [ ] Secrets known to have been world-readable and **not rotated**  
- [ ] Owner has not signed this checklist  

### Conditional GO (limited pilot) only if

- All NO-GO boxes cleared **or** residual items explicitly accepted in writing with expiry dates  
- Pilot limited to named test patients/doctors  
- Enhanced monitoring enabled  
- Rollback DNS/Tunnel plan tested  

### Full GO (broader patients/doctors)

- Conditional GO items plus: SQL TLS validated, service account migration done, **access-code expiry/rotation implemented and verified**, Cloudflare Access Staff/Admin policies verified (admin MFA), backup/restore evidence scheduled into H.6.7, H.6.4 security audit scheduled  

**Unresolved until implementation evidence exists** (not fixed by planning docs):

- HTTP exposure and direct-origin containment  
- Broad TCP 3003 firewall rules  
- Excessive ACLs on secrets, storage, logs, and backups  
- SYSTEM-run application tasks/process  
- SQL encryption and certificate validation  
- Production CORS and HTTPS configuration  
- Host-based portal enforcement  
- Staff/Admin access restrictions (Access decided, not configured)  
- Credential rotation following the exposure window  
- Patient access-code expiry/rotation (policy decided, not implemented)
